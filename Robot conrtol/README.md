# robot_driver — драйвер трёхколёсного омни-робота

Python-модуль для управления роботом на трёх омни-колёсах по UDP (Wi-Fi).
Это версия **без ручного управления**: клавиатура и библиотека `keyboard` убраны,
остался только драйвер. Его задача — принять желаемое движение
`(vf, vl, w)` и превратить его в команду моторам. Автоматическое управление
(регулятор, обратная связь с камеры) пишется поверх него.

Зависимостей нет — только стандартная библиотека Python 3.

## Файлы

| Файл | Назначение |
|---|---|
| `robot_driver.py` | Сам драйвер (класс `Robot` и вспомогательные функции) |
| `robot_config.json` | Конфиг: геометрия колёс, пины, калибровка моторов |
| `example_auto.py` | Минимальный пример цикла автоматического управления |

## Быстрый старт

```python
from robot_driver import Robot, SEND_INTERVAL
import time

with Robot.connect("robot_config.json") as robot:
    while нужно_ехать:
        vf, vl, w = мой_регулятор(...)     # доли от 1
        robot.drive(vf, vl, w)             # ОДНА команда
        time.sleep(SEND_INTERVAL)          # ~20 Гц
# при выходе из with робот автоматически получает STOP
```

Запуск без робота для проверки математики:

```python
from robot_driver import load_config, make_packet
cfg = load_config("robot_config.json")
print(make_packet(cfg, 0.5, 0, 0))   # -> "M:-178,0,-178,250"
```

## Главное, что нужно знать

1. **Команду нужно повторять.** Каждая команда живёт `command_ms` мс (250 по умолчанию),
   после чего робот сам останавливается. Это защита от потери связи. Поэтому
   `drive()` надо вызывать регулярно, пока робот должен ехать — рекомендуется каждые
   50 мс (20 Гц, константа `SEND_INTERVAL`). Прошивка принимает `command_ms` не больше 1000.
2. **Скорости — безразмерные доли от 1, а не м/с и не рад/с.** `vf = 0.5` значит
   «примерно половина мощности», реальная скорость зависит от батареи, пола, массы.
   Для точных перемещений нужна обратная связь по камере (регулятор по положению),
   либо отдельная калибровка «доля → м/с».
3. **Мёртвая зона `dz` создаёт скачок.** В текущем конфиге `dz = 0.7`: любая ненулевая
   команда, у которой по колесу получилось меньше 70% ШИМ, **поднимается до 70%**
   (~178 из 255). То есть малые скорости фактически недостижимы: между «стоим» и
   «едем на 70%» нет плавного перехода. Для регулятора это сильная нелинейность
   (возможны колебания возле цели). Варианты: учитывать в регуляторе, снижать `dz`
   после замеров, либо подавать нулевую команду вместо очень малых.
4. **Рядом с порогом направление может слегка искажаться**, потому что `dz`
   применяется к каждому колесу отдельно (см. «Как считается команда»).
5. **Робот отвечает** на пакеты (`OK` / `ERR...`). Если ответов нет больше ~2 с,
   связь, скорее всего, потеряна (`robot.seconds_since_reply()`).

## Система координат и знаки

Все направления — в системе робота:

| Параметр | Положительное значение | Отрицательное |
|---|---|---|
| `vf` | вперёд | назад |
| `vl` | влево | вправо |
| `w`  | вращение **против** часовой стрелки | по часовой |

Колёса (углы отсчитываются от «вперёд» против часовой стрелки):

```
            0° (вперёд)
     колесо 1 (60°)   колесо 3 (300°)
  90° (лево)                      270° (право)
            колесо 2 (180°, сзади)
```

Если у другого робота колёса стоят иначе — меняется только `wheel_angles_deg` в конфиге.

## API

### `Robot.connect(config_path="robot_config.json", timeout=30.0, interactive=True, verbose=True, push_pins=True) -> Robot`
Читает конфиг, ищет робота по маякам, отправляет пины. Исключения:
`RobotNotFound` (не нашли за `timeout` с), `RobotError` (несколько роботов при
`interactive=False`, либо робот не принял пины).
- `interactive=False` — не спрашивать номер в консоли; для автоматических запусков
  задайте `robot_id` в конфиге.
- `verbose=False` — не печатать команды в терминал.

### `robot.drive(vf, vl, w) -> str`
Отправляет **одну** команду и возвращает отправленную строку (`"M:a,b,c,t"` или `"STOP"`).
Не блокирует. Вектор `(vf, vl)` обрезается по длине до `drive_speed`, `|w|` — до `turn_speed`
(это потолки скорости из конфига). Если все три нули — отправляется `STOP`.

### `robot.stop()`
Немедленная остановка.

### `robot.hold(vf, vl, w, seconds)`
Блокирующий: повторяет `drive()` с частотой 20 Гц `seconds` секунд, затем `stop()`.
Удобно для простых тестов, для регулятора обычно не нужно.

### `robot.poll() -> list[str]`
Читает накопившиеся ответы робота (не блокирует). `drive()` и `stop()` уже вызывают
её сами, отдельно нужна только если вы долго не шлёте команды.

### `robot.seconds_since_reply() -> float`
Секунд с момента последнего ответа робота.

### `robot.push_pins(tries=5) -> bool`
Отправляет пины моторов из конфига (они сохраняются во флеше робота).
Вызывается из `connect()`; вручную обычно не нужна.

### `robot.test_motors(should_abort=None)`
Каждый мотор по очереди 2 с вперёд и 2 с назад **напрямую**, без калибровки
(`gain/dz/inv` не применяются) — проверка железа и пинов. `should_abort` —
необязательная функция, вернувшая `True` прерывает тест; `Ctrl+C` тоже прерывает.

### `robot.close()`
Три раза шлёт `STOP` и закрывает сокет. Вызывается автоматически при выходе из `with`.
Если не используете `with`, вызывайте в `finally`.

### Функции без сети (удобно для тестов)
- `load_config(path)` — загрузка конфига с подстановкой значений по умолчанию;
- `make_packet(cfg, vf, vl, w)` — `(vf, vl, w)` → строка команды;
- `wheel_speeds(vf, vl, w, angles)` — кинематика (доли скорости колёс);
- `calibrate(u, cfg)` — доли скорости колёс → напряжение на моторы;
- `find_robots(seconds)` / `pick_robot(cfg, timeout, interactive)` — поиск робота.

## Как считается команда

1. **Ограничение скорости**: длина `(vf, vl)` ≤ `drive_speed`, `|w|` ≤ `turn_speed`.
2. **Кинематика** (`wheel_speeds`): для колеса, стоящего под углом `a`,
   `u = vl·cos(a) − vf·sin(a) + w`. Если `max|u| > 1`, все три колеса масштабируются вместе
   (направление сохраняется).
3. **Калибровка** (`calibrate`):
   - `u / gain` — слабый мотор получает больше; если кому-то выходит больше 100%,
     масштабируются все три;
   - значения меньше 1% обнуляются;
   - ненулевые поднимаются минимум до `dz` (порог страгивания);
   - `inv: true` инвертирует знак.
4. **Перевод в ШИМ**: `round(x·255)`, целые −255..255.
5. Формируется `"M:a,b,c,t"`, где `t = command_ms`. Если команда нулевая — `"STOP"`.

## Протокол (UDP)

Порты: маяки робота на **8889** (broadcast), команды на порт робота (по умолчанию **8888**,
приходит в маяке).

| Направление | Сообщение | Смысл |
|---|---|---|
| робот → ПК | `ROBOT:<id>;IP:<ip>;PORT:<port>` | маяк; по нему находим робота |
| ПК → робот | `PINS:i1,i2,en1,i1,i2,en2,i1,i2,en3` | пины моторов (IN1, IN2, EN для каждого) |
| ПК → робот | `M:a,b,c,t` | ШИМ моторов −255..255, время действия `t` мс |
| ПК → робот | `STOP` | остановка |
| робот → ПК | `OK` / `ERR...` | подтверждение / ошибка |

Положительный ШИМ мотора = `IN1 HIGH`.

## Конфиг `robot_config.json`

| Поле | Значение |
|---|---|
| `robot_id` | id робота (печатается в Serial при старте, приходит в маяке). Пусто = взять единственного найденного |
| `wheel_angles_deg` | положение колёс вокруг центра, градусы (см. схему выше) |
| `drive_speed` | потолок длины вектора `(vf, vl)`, 0..1 |
| `turn_speed` | потолок `|w|`, 0..1 |
| `command_ms` | время жизни команды, мс (≤ 1000) |
| `test_pwm` | ШИМ для `test_motors()` |
| `motors.N.pins` | `[IN1, IN2, EN]` мотора N |
| `motors.N.gain` | максимальная скорость относительно самого сильного мотора (слабый < 1) |
| `motors.N.inv` | инверсия направления мотора |
| `motors.N.dz` | порог страгивания, доля ШИМ 0..1 |

Текущие значения: `drive_speed = turn_speed = 0.9`, `command_ms = 250`,
`dz = 0.7` у всех моторов, мотор 3 инвертирован (`inv: true`).
Поля, начинающиеся с `_` (например `_help_...`), — просто комментарии, код их игнорирует.

## Рекомендации тому, кто делает автоматическое управление

- Весь расчёт идёт на компьютере, на робота уходят только команды `M:` — никакой логики
  движения в прошивке нет.
- Держите частоту отправки 20 Гц (или выше, но не ниже ~1/`command_ms`). Если
  регулятор считает медленнее, увеличьте `command_ms` (не более 1000) — но тогда
  робот дольше «доезжает» после потери связи.
- Регулятор лучше строить по положению с камеры (ошибка по `x`, `y`, `θ` → `vf, vl, w`),
  переводя ошибку из мировой системы в систему робота поворотом на `θ`.
  Помните про знаки: `w > 0` — против часовой.
- Из-за `dz` (скачок до ~70% ШИМ) имеет смысл либо использовать «ехать/стоять» с
  торможением заранее, либо замерить `dz` заново и снизить его, либо работать
  короткими импульсами.
- Для проверки перед запуском: `robot.test_motors()` — каждое колесо должно крутиться
  «вперёд» в тесте согласованно с конфигом; если какой-то мотор крутится не туда,
  меняйте `inv`, а не знаки в коде.
- Обязательно оборачивайте управление в `with Robot.connect(...)` или `try/finally`,
  чтобы при исключении робот получил `STOP`.
